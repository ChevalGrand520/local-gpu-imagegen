# 中文阅读摘要（不放入英文投稿 PDF）

本地图像生成客户端丢失提交响应后，可能无法判断后端是否已接受或执行请求。
本文描述一套受证据约束的恢复工具，包括版本化证据导出器、同一 run 内的保守
重发保护，以及受控故障注入与后端观察。工具分别保留产品报告状态、解释状态
和 oracle 证据，不把缺失的任务标识或恢复结果补写为已知。既有 CPU 配对记录
覆盖正常控制、提交响应丢失及已知任务的完成响应丢失。Windows/ComfyUI 的四个
固定案例均具备留存执行绑定；正常案例各有一次提交和执行，注入案例各有两次。
第二次调用在观察到首次执行完成后新建 run，并改变 seed，因此不能视为原 run
自动恢复或减少真实重复执行。论文的贡献限于可检查的状态区分、恢复作用域和
观察工具，不估计部署故障率、自然重复执行率或图像质量优势。

关键词：模糊提交；恢复作用域；执行证据；故障注入；本地生成式 AI。
English keywords: ambiguous submission; recovery scope; execution evidence;
fault injection; local generative AI.
