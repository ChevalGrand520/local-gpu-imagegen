## 采纳与修正

- §2.2 先说明功能：尝试被记录为 unknown 时，守卫阻止同一 run 再次自动
  提交。限制随后说明；F02 的未完成代价与 FPRE 的误阻塞均保留。
- §4 补充操作者调用 local_gpu_get_run、检查尝试和恢复动作，以及已知 job ID
  的恢复步骤；补充可借助记录研究的问题，不新增采用或生产率证据。
- 修正建议中的实质推断：unresolved + unknown 本身无法区分已接受任务与
  发送前失败，必须结合后端历史或传输证据。检索不会自动消除这个歧义。
- 摘要恢复 general reliability / GPU savings 边界；结论明确对照为 synthetic。
- 不使用“每个 run 最多一次提交”的无条件表述：已完成轮次、其他 run、
  其他进程不属于本条 unknown-outcome 守卫保证。少发请求不等于少做计算。
  缓存记录不提供重复任务边际 GPU 成本测量。
- 修复 N1：验证材料及补充包链接固定到 dc9720ee76375ea341a8770c4ef32c0143b3a1ff。

  receipt 和 demo 六个路径在该提交存在。产品与 Windows 源码快照保持分离。
- 处理 N2/N5：Figure 2 保留 SVG，PNG 提升到 7000×1600；stop-only 使用
  虚线无箭头连接并标注 unchanged。未把 DPI 惯例冒充当前期刊强制要求。
- N6 在原审查中已撤回；Figure 1 已有 derived checker，无需追加组件。
